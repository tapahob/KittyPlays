# KittyPlays

Видеоплеер для Windows с русским интерфейсом. Откройте `target\release\kittyplays.exe`, вставьте ссылку на YouTube или выберите файл кнопкой «Обзор». Выберите режим и нажмите «Воспроизвести». В окне видео пробел ставит просмотр на паузу, стрелки перематывают, F переключает полный экран, I показывает статистику, Q закрывает видео.

## Режимы

Поверх видео видны исходный и текущий FPS. В настольном плеере текущая частота оценивается по продвижению видео за реальное время с учётом пропусков. На паузе она падает до нуля. Для записей завершённых трансляций YouTube с нумерованными фрагментами без индекса плеер строит временный список сегментов для перемотки.

### Просмотр на странице YouTube в Chrome

Режим интерполяции, лимит FPS и состояние кнопки **Info** сохраняются в профиле Chrome и восстанавливаются при открытии страницы YouTube.

**NVIDIA VFG** использует отдельный локальный модуль для совместимой видеокарты NVIDIA и учитывает выбор **60**, **120** или **Max** в меню FPS. В Max цель определяется по частоте обновления вкладки на текущем мониторе. Модуль может вставлять до семи промежуточных кадров на пару исходных. Разрешение обработки снижается, если передача кадров между Chrome и модулем задерживается. Для установки на Windows x64 нужны Python 3.14 и Rust с инструментами MSVC. Скопируйте ID расширения из `chrome://extensions` и выполните из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-vfg.ps1 -ExtensionId ID_РАСШИРЕНИЯ
```

Chrome запускает модуль при выборе NVIDIA VFG. Если Chrome спросит разрешение на доступ к локальной сети, разрешите его для YouTube. Кадры передаются по loopback на том же компьютере. [Поддерживаемые видеокарты](https://docs.nvidia.com/maxine/vfx/latest/Filters/VideoFrameGeneration.html)

Откройте `chrome://extensions`, включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите папку `chrome-extension` из проекта. Обновите открытую страницу ролика. Нажатие на значок KittyPlays включает или выключает обработку в текущей вкладке.

В версии 1.2.0 на страницах YouTube по умолчанию работает нейросеть Framegen tfact2, обученная методом дистилляции на результатах RIFE_m. Веса поставляются вместе с расширением. Обработка идёт на локальной видеокарте через WebGPU. Название активного режима видно перед счётчиком FPS. Если нейросеть не запускается, расширение включает предыдущий алгоритм WebGL и показывает «Оптический поток».

Нейросеть вычисляет общие признаки пары кадров один раз и использует их для промежуточных моментов. На RTX 4090 сеть оценивает движение при 1280 × 720 и формирует изображение из текстур исходного разрешения. Расширение пропускает почти одинаковые кадры и старается сохранить резкую склейку сцен. На быстрых перекрытиях всё ещё возможны искажения. Буфер в 2,25 исходного кадра добавляет около 75 мс задержки изображения при 30 FPS. Счётчик показывает исходную частоту и число отрисованных кадров за последнюю секунду.

Под FPS раз в секунду обновляется оценка ресурсов. Процент GPU показывает долю прошедшего времени, занятую подготовкой пар и генерацией кадров нейросетью. Расширение выборочно измеряет эти операции таймером видеокарты и учитывает число выполненных вызовов. Прочерк означает, что замер недоступен. Видеопамять указана в МиБ по размерам выделенных расширением рабочих буферов и текстур.

Движок и веса взяты из Framegen v1.5.6. Код движка распространяется по MIT. Веса разрешены для личного использования и некоммерческих исследований. Условия и атрибуция находятся в папке `chrome-extension/neural`. [Исходная версия Framegen](https://github.com/MONZikWasTaken/Framegen/tree/e040a135df5cd11c03534aecc782878e412a27c7) · [Условия использования весов](chrome-extension/neural/WEIGHTS_LICENSE.md).

### Настольный плеер

- **Видеокарта, 120 кадров в секунду.** Режим по умолчанию. Фильтр libplacebo смешивает соседние кадры с весами, которые зависят от времени показа. Частота потока после фильтра составляет 120 кадров в секунду, в том числе на экране с частотой 144 герца. При быстром движении возможно двоение контуров. Для просмотра всех промежуточных кадров нужен экран с частотой от 120 герц и достаточная производительность.
- **Процессор, компенсация движения.** Фильтр FFmpeg minterpolate оценивает перемещение блоков и строит промежуточные кадры по векторам движения. Для обнаружения смены сцены используется разница между кадрами. Целевая частота составляет 120 кадров в секунду. Обработка может отставать даже на небольших разрешениях.
- **Исходная частота.** Аппаратное декодирование, когда его поддерживает видеокарта, и воспроизведение с исходными временными метками.

Приложение написано на Rust. За декодирование, синхронизацию со звуком и вывод отвечает нативный движок mpv. yt-dlp получает адреса аудио и видео с YouTube. Кадры обрабатываются локально. В режиме видеокарты используется Vulkan для интерполяции и Direct3D 11 для вывода. Закреплённая сборка фильтра принимает кадры из оперативной памяти, поэтому аппаратный декодер работает с копированием. Rust управляет плеером и не копирует пиксели между кадрами.

## Сборка

Для сборки нужны Rust stable с инструментарием MSVC, компоновщик Visual Studio C++ и Windows SDK. Из корня проекта выполните команды в PowerShell.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
cargo test
cargo build --release
.\target\release\kittyplays.exe
```

Скрипт загружает закреплённые версии mpv, yt-dlp и Deno в папку `tools` и проверяет SHA-256. Для запуска готовой сборки достаточно оставить эту папку в проекте или положить её содержимое рядом с приложением.

## Проверка производительности

Консольная версия принимает тот же источник и режим `gpu`, `motion` или `native`. Переменная `KITTYPLAYS_STATS` включает вывод исходной частоты, оценки частоты после фильтра и счётчиков пропущенных кадров. Для обычного просмотра её можно удалить из окружения.

```powershell
$env:KITTYPLAYS_STATS = "1"
.\target\release\kittyplays-cli.exe --mode gpu "C:\Видео\пример.mp4"
.\target\release\kittyplays-cli.exe --mode motion "C:\Видео\пример.mp4"
Remove-Item Env:\KITTYPLAYS_STATS
```

На RTX 4090 и Ryzen 7 9800X3D восьмисекундный тест H.264 со звуком, 1920 × 1080 при 30 кадрах в секунду, прошёл в реальном времени. В режиме видеокарты фильтр выдавал 120 кадров в секунду, оба счётчика пропусков остались на нуле. Публичный ролик YouTube «Me at the zoo» также воспроизвёлся целиком. В режиме компенсации движения шестисекундный тест 640 × 360 при 24 кадрах в секунду занял около 18 секунд. Частота после фильтра описывает временные метки, а скорость воспроизведения и пропуски показывают, успевает ли машина.

## План реализации

1. Подключить движок mpv, локальные фильтры интерполяции и синхронизацию звука.
2. Сделать окно Windows с выбором файла, ссылки и режима.
3. Подключить yt-dlp и Deno, закрепить версии и автоматизировать установку.
4. Объединить компоненты, собрать релиз и проверить локальное видео и YouTube. Измерить частоту и пропуски на реальном оборудовании.
